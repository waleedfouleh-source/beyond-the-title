# ما وراء العنوان | Beyond the Title

منصة مهنية عربية: الباحث عن عمل يرفع CV ويحصل على تقرير وخطة وتوصيات مبنية على **مرجعية مرام المعتمدة**.

## الحالة الحالية (صريحة)
- يعمل فعليًا: تسجيل/دخول، أدوار (admin / consultant / candidate / employer)، رفع CV خاص، إدخال مرام للمرجعية كمسودات، اعتماد وليد، ظهور المرجعية المعتمدة في التقرير والخطة والمستشار، الوظائف، الدورات، طلبات الشركات.
- **تحليل الـCV بالذكاء الاصطناعي:** جاهز عبر `supabase/functions/analyze-cv` (Gemini). يعمل بعد نشر الدالة وإضافة `GEMINI_API_KEY` (انظر SETUP.md). بدونها يظهر تقرير اختبار موسوم بوضوح.
- **المستشار** ما زال يبحث في مرجعية مرام بالكلمات (ليس نموذجًا لغويًا بعد).

## الملفات
`index.html` · `main.js` (كل منطق الواجهة) · `style.css` · `config.js` (مفاتيح عامة فقط) · `supabase/schema.sql` · `.github/workflows/pages.yml`

## النشر
GitHub Pages ينشر فقط: index.html, main.js, style.css, config.js, maram.png (ملفات SQL والتوثيق لا تُنشر).


## مراجعة السير الذاتية (17 أكتوبر 2026)
- تكتب مرام تعليماتها للذكاء الاصطناعي من أعلى لوحتها في قسم «توصيات مرام للذكاء الاصطناعي». لا تدخل التوصيات حيز الاستخدام قبل اعتماد الإدارة.
- في لوحة مرام ولوحة وليد: تظهر السيرة الأصلية والنسخة المعدلة والأسئلة والإجابات والنبذة المهنية للمتقدم.
- في حساب المتقدم: تظهر بطاقتان للسيرة الأصلية والمعدلة مع العرض والتنزيل؛ تبقى البيانات محفوظة عند العودة للحساب.
- تحفظ عملية الرفع الملف في \`profiles\` حتى عند فشل تحليل Gemini؛ ولا تُعرض نسخة معدلة لم تُنشأ بالفعل.
- **مهم لمدير المشروع:** للوصول إلى ملفات المتقدمين من حساب مرام/وليد، افتح مشروع Supabase المرتبط بالموقع (\`obndotlxnzkiaalycumh\`) وشغّل \`supabase/staff_cv_access.sql\` في SQL Editor بصلاحية مالك المشروع. لا تطبق الملف على مشروع آخر، ولا تنشر مفتاح \`service_role\`.
- صلاحيات الوصول تستخدم RLS: المتقدم يقرأ ملفاته، ومرام ووليد يقرآن ملفات المتقدمين ذات الصلة فقط، ولا تتاح الملفات لمستخدمين آخرين.
- الواجهة نُشرت من GitHub Pages، لكن خصائص عرض ملفات المتقدمين لمرام ووليد تعتمد على تفعيل تحديث قاعدة البيانات أعلاه. اختبار الدخول الفعلي بحسابات مرام ووليد والمتقدم لا يزال مطلوبًا.

## تنبيه الصيانة والتحديثات
- تنبيه أعلى الموقع يظهر للزوار فقط عندما تكون `active` في ملف `maintenance.json` مساوية لـ `true`.
- قبل تنفيذ تحديث كبير: غيّر `active` إلى `true`، واحفظ التعديل، وانتظر نجاح نشر GitHub Pages قبل إجراء تعديلات المنصة.
- عند الانتهاء والتأكد من نجاح النشر: أعد `active` إلى `false` ليختفي التنبيه بعد النشر.
- يمكن تعديل نص التنبيه من `title` و`message`. يتحقق الموقع من الحالة كل 60 ثانية دون إعادة تحميل أو تغيير بيانات الحسابات.
- **مهم:** التفعيل والإيقاف يدويان، ولا يكتشف الموقع تلقائيًا تعديل الملفات. التنبيه إعلامي ولا يوقف رفع الملفات أو دخول المستخدمين.
